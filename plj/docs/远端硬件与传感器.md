```text

                         │                                      │

                         │                                      │
```

当前系统可以分成两条链路：

| 链路 | 作用 | 当前状态 |
|------|------|----------|
| ROS 2 感知 / SLAM | L1 点云、IMU、定位、台阶检测、爬楼触发 | 远端有 L1 参考驱动；本项目自研包在资料中标为本机已有、远端未部署 |
| 电机 Web 执行层 | 升降、后侧驱动、履带、转向的串口控制 | 远端 `~/pythonProject` 已有，文档已整理 |

## 4. 执行机构与电机链路

电机控制由远端 `~/pythonProject` 提供 Web/API，监听 `0.0.0.0:8080`。它不是 ROS 2 节点，而是 Python `HTTPServer` 将浏览器/API 请求转成串口指令。

| 执行机构 | 串口 | 波特率 | 模块 | 控制模型 |
|----------|------|--------|------|----------|
| 升降机构 | `/dev/serial2` | 57600 | `lift_motor_control.py` | 前升降机构暂记为 7，后升降机构暂记为 8；用于上下升降、支撑和姿态调整 |
| 后侧驱动 | `/dev/serial3` | 9600 | `rwd_control.py` | `speed + dir`，支持双轮同步和差速 |
| 履带行走 | `/dev/serial1` | 9600 | `chassis_control.py` | `speed + dir`，履带是普通直行和爬楼的主动力 |
| 履带底盘转向 | `/dev/serial4` | 115200 | `zhuanxiang_control.py` | `target_position + speed`，用于履带底盘转向定位，可支持 `+90°/-90°` 后横移 |

典型接口：

| 功能 | HTTP 接口 |
|------|-----------|
| 升降上升 | `/forward_1?motor=1\|2` |
| 升降下降 | `/backward_1?motor=1\|2` |
| 读升降限位 | `/read_state?motor=1\|2` |
| 后侧驱动 | `/chassis_motor_run?id=&speed=&dir=` |
| 履带行走 | `/dipan_motor_run?id=&speed=&dir=` |
| 履带底盘转向定位 | `/zhuanxiang_motor_run?target_position=&zhuanxiang_speed=` |

完整协议、寄存器和半自动运动逻辑见 [电机控制系统.md](./电机控制系统.md)。

### 4.1 运动模式口径

当前讨论确认的运动逻辑如下：

| 运动模式 | 机构状态 | 主要执行 |
|----------|----------|----------|
| 履带直行 | 履带接地，`1/2/5/6` 轮子悬空 | 履带前进/后退 |
| 后轮差速转向 | 前后升降同时下降一定高度，反推车体上升，后轮 `5/6` 接地 | 后侧双驱差速 |
| 履带底盘横移 | 前后升降抬起车体，履带底盘转 `+90°/-90°` 后重新接地 | 履带前进/后退变成横向移动 |
| 爬楼助推 | 履带为主动力；需要越过卡点时，前后升降同时上升到合适位置 | 后侧双驱短距离助推，然后履带继续主推进 |

### 4.2 现场编号口径

以下编号来自现场照片和人工标注，只用于结构沟通，不在本文推导运动策略：

| 编号 | 暂定名称 | 备注 |
|------|----------|------|
| `1` | 前左轮 | 用户确认：前左右轮之一 |
| `2` | 前右轮 | 用户确认：前左右轮之一 |
| `3` | 中间左支撑轮 | 用户确认：中间支撑轮 |
| `4` | 中间右支撑轮 | 用户确认：中间支撑轮 |
| `5` | 后左轮 | 用户标注为后轮 |
| `6` | 后右轮 | 用户标注为后轮 |
| `7` | 前升降机构 / 前升降电机 | 暂定名称 |
| `8` | 后升降机构 / 后升降电机 | 暂定名称 |

另有履带底盘，用户确认其可以转向；本文暂不把履带底盘并入 `1`-`8` 编号。

编号提醒：Web 参数里的 `motor=1/2`、`id=1/2` 是各控制器内部地址，不等于现场机械编号 `1/2`。后侧驱动大概率对应机械编号 `5/6`，升降机构大概率对应 `7/8`，但左右/前后的精确映射仍需低速实测确认。

## 5. USB / 设备节点速查

常用设备文件：

```text
/dev/unilidar_serial4     # Unitree L1，指向 ttyCH341USB4
/dev/serial1              # 履带
/dev/serial2              # 升降
/dev/serial3              # 后侧驱动
/dev/serial4              # 转向
```

快速检查：

```bash
ls -l /dev/unilidar_serial4 2>/dev/null || true
ls -l /dev/serial1 /dev/serial2 /dev/serial3 /dev/serial4 2>/dev/null || true
lsusb
```

## 6. ROS 2 话题速查

资料中规划/预留的关键 ROS 2 信号如下。除 `/unilidar/cloud` 来自远端已有参考驱动外，其余本项目信号按设计文档属于本机代码/待部署链路，不能视作远端已运行。

| 话题 / TF | 发布方 | 用途 |
|-----------|--------|------|
| `/unilidar/cloud` | L1 输入层 | 3D 点云输入，供 SLAM 和台阶检测使用 |
| `/unilidar/imu` | L1 输入层 | L1 内置 IMU 数据，供 LiDAR-IMU 前端和姿态判断使用 |
| `/frontend/odom` | `slam_frontend` | 本项目轻量前端里程计 |
| `/frontend/path` | `slam_frontend` | 前端轨迹调试 |
| `/frontend/local_map` | `slam_frontend` | 前端局部点云地图 |
| `/stair_detected` | `stair_detector` | 前方是否稳定检测到台阶 |
| `/stair_info` | `stair_detector` | 台阶高度、距离、宽度、置信度等 |
| `/front_roi_cloud` | `stair_detector` | 前方 ROI 点云调试 |
| `/climb_mode_trigger` | `climb_supervisor` | 请求底盘进入爬台阶模式 |
| `/normal_mode_trigger` | `climb_supervisor` | 请求底盘恢复普通模式 |
| `/slam_backend_pause` | `climb_supervisor` | 爬楼期间暂停/恢复后端建图 |
| `/localization_reinit` | `climb_supervisor` | 爬完后请求重定位 |
| `map -> odom -> base_link` | SLAM / 定位后端 | 定位与感知坐标链 |

注意：这些信号属于 ROS 2 SLAM/感知方案。电机 Web 当前走 HTTP + 串口，两者之间的真实闭环仍需实现和联调。

## 7. 快速探测命令

SSH 登录见 [远端登录.md](./远端登录.md)。登录后可用：

```bash
# 系统
hostname
uname -a
df -h /
free -h

# ROS 2
source /opt/ros/humble/setup.bash
echo $ROS_DISTRO
ros2 --help >/dev/null && echo ros2_ok

# 设备
ls -l /dev/unilidar_serial4 2>/dev/null || true
ls -l /dev/serial1 /dev/serial2 /dev/serial3 /dev/serial4 2>/dev/null || true
```

如果已经启动 L1 驱动或本项目 ROS 2 节点：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list
ros2 topic hz /unilidar/cloud
ros2 node list
```

电机 Web 检查：

```bash
cd ~/pythonProject
python3 main.py
```

浏览器访问：

```text
http://172.0.0.67:8080/
```
