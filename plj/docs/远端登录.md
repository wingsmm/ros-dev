# 远端登录说明

本文档只说明如何从 Windows 本机登录爬楼机器人 Jetson 主机，以及登录后如何检查 ROS 2 环境和电机 Web 服务。硬件、SLAM、半自动运动逻辑和电机接口分别见 [项目备忘.md](./项目备忘.md)、[SLAM系统方案.md](./SLAM系统方案.md) 与 [电机控制系统.md](./电机控制系统.md)。

---

## 1. 实测连接信息

| 项目 | 值 |
|------|-----|
| 主机名 | `nvidia-desktop` |
| 有线 IP | `172.0.0.67` |
| Wi-Fi IP | `172.0.0.50` |
| SSH 用户 | `nvidia` |
| 系统 | Ubuntu 22.04.5 LTS / Jetson Orin / ROS 2 Humble |
| 项目电机 Web | `http://172.0.0.67:8080/` 或 `http://172.0.0.50:8080/` |
| 远端电机工程 | `~/pythonProject` |

登录前先确认 PC 与 Jetson 在同一局域网：

```powershell
ping 172.0.0.67
ping 172.0.0.50
```

如果 IP 变化，以现场实际地址为准，后续命令中的 `172.0.0.67` / `172.0.0.50` 同步替换。

### 1.1 当前连通性测试

2026-06-02 在 Windows 本机测试：

| 目标 | 端口 | 结果 | 说明 |
|------|------|------|------|
| `172.0.0.50` | `22` | 通过 | `Test-NetConnection` 成功；SSH 只读登录返回 `nvidia-desktop` / `nvidia` |
| `172.0.0.50` | `8080` | 通过 | `Test-NetConnection` 成功，说明电机 Web 端口可达 |

测试命令：

```powershell
Test-NetConnection -ComputerName 172.0.0.50 -Port 22
Test-NetConnection -ComputerName 172.0.0.50 -Port 8080
ssh nvidia@172.0.0.50
```

## 2. OpenSSH 登录（推荐）

在 PowerShell、CMD 或 Cursor 终端执行：

```powershell
ssh nvidia@172.0.0.67
# 或使用 Wi-Fi IP
ssh nvidia@172.0.0.50
```

首次连接会要求确认主机指纹，输入 `yes` 后回车，再输入远端用户密码。

登录后建议先检查主机和基础环境：

```bash
hostname
uname -a
df -h /
free -h
```

## 3. PuTTY / plink

PuTTY 适合图形登录，`plink` 适合脚本里一次性执行命令。本机常见路径：

```text
C:\Program Files\PuTTY\plink.exe
```

当前 Jetson SSH 主机指纹：

```text
SHA256:0Gyitz4pEe4xJjxVn0NDq33RRg+Sydhg7K91rLyK/Y0
```

PowerShell 一次性执行远程诊断命令：

```powershell
$plink = "C:\Program Files\PuTTY\plink.exe"
$hostkey = "SHA256:0Gyitz4pEe4xJjxVn0NDq33RRg+Sydhg7K91rLyK/Y0"

& $plink -ssh nvidia@172.0.0.67 -batch -hostkey $hostkey "hostname; uptime; df -h /; free -h"
# 或使用 Wi-Fi IP
& $plink -ssh nvidia@172.0.0.50 -batch -hostkey $hostkey "hostname; uptime; df -h /; free -h"
```

交互式 plink 会话：

```powershell
& $plink -ssh nvidia@172.0.0.67 -hostkey $hostkey
# 或使用 Wi-Fi IP
& $plink -ssh nvidia@172.0.0.50 -hostkey $hostkey
```

说明：

| 参数 | 作用 |
|------|------|
| `-batch` | 非交互模式，避免脚本卡在提示上 |
| `-hostkey` | 固定主机密钥，避免首次连接确认 |
| `-ssh nvidia@172.0.0.67` / `-ssh nvidia@172.0.0.50` | 指定 SSH 用户和主机 |

密码不写入本文档。建议配置 SSH 公钥登录，或只在受控终端里手动输入密码。

## 4. ROS 2 环境检查

非交互 SSH 默认可能看不到 `ros2` 命令，先加载 ROS 2 Humble：

```bash
source /opt/ros/humble/setup.bash
ros2 --help >/dev/null && echo ros2_ok
echo $ROS_DISTRO
```

如果本项目工作区已经在远端部署并构建，再加载工作区：

```bash
source ~/other/install/setup.bash
```

当前资料里的本地/远端边界是：`plj` 资料和本仓库代码不应自动覆盖远端工作区；如需同步、部署或远端验证，先明确同步路径和命令，再执行。

常用检查：

```bash
source /opt/ros/humble/setup.bash
ros2 topic list
ros2 node list
```

若提示找不到 `ros2`，通常是没有执行 `source /opt/ros/humble/setup.bash`。

## 5. 电机 Web 服务

电机 Web 工程在远端：

```bash
cd ~/pythonProject
python3 main.py
```

浏览器访问：

```text
http://172.0.0.67:8080/
http://172.0.0.50:8080/
```

服务启动后会初始化四路串口：

| 串口 | 用途 |
|------|------|
| `/dev/serial1` | 履带 |
| `/dev/serial2` | 升降 |
| `/dev/serial3` | 后侧驱动 |
| `/dev/serial4` | 转向 |

电机控制接口和半自动运动逻辑见 [电机控制系统.md](./电机控制系统.md)。

## 6. 登录后的常用检查

```bash
# 系统
hostname
uptime
df -h /
free -h

# ROS 2
source /opt/ros/humble/setup.bash
echo $ROS_DISTRO
ros2 --help >/dev/null && echo ros2_ok

# 设备
ls -l /dev/unilidar_serial4 2>/dev/null || true
ls -l /dev/serial1 /dev/serial2 /dev/serial3 /dev/serial4 2>/dev/null || true
```

如果正在运行 ROS 2 传感器或 SLAM 节点，可继续检查：

```bash
ros2 topic list
ros2 topic hz /unilidar/cloud
```

## 7. 常见问题

| 现象 | 处理 |
|------|------|
| `ping` 不通 | 检查 Jetson 是否上电、网络是否同段、IP 是否变化 |
| SSH 连不上 | 确认用户是 `nvidia`，检查局域网、防火墙和主机 IP |
| 主机指纹变更警告 | Jetson 重装或 SSH 密钥变化后，删除 `C:\Users\<你>\.ssh\known_hosts` 中对应行再连 |
| `ros2: command not found` | 执行 `source /opt/ros/humble/setup.bash` |
| Web 能打开但电机不动 | 检查 `python3 main.py` 是否运行、串口是否存在、接口是否调对 |
| `/data` 没有实时转向数据 | `zhuanxiang_control.start_receive()` 当前可能未启用，详见电机文档 |
| 远端工作区没有本项目包 | 当前资料不代表已部署；部署前需明确同步范围并确认 |

## 8. 安全提示

- 不把 SSH 密码、Web 凭据或一次性登录脚本写进公开仓库。
- 电机 Web 绑定 `0.0.0.0:8080`，局域网内均可访问，无鉴权；不要暴露到公网。
- 未经当前对话明确同意，不执行远端部署、上传、同步或覆盖远端文件。
