四、为什么入口和原 Release 不完全一样

原 Release 的 launcher 是：

   com.robotca.ControlApp.ControlApp

但当前源码直接冷启动 ControlApp 时，ROBOT_INFO 为空，会在启动时崩溃。因此当前重新编译版把 launcher 调整为：

   com.robotca.ControlApp.RobotChooser

这样启动后先进入机器人选择界面，再进入控制界面，至少能正常打开和测试。

六、SLAM 地图与 A-B-A 导航状态

当前 SLAM 地图页面已经具备 A/B 点导航 UI：

   设 A、设 B、去 B、返回 A、A-B-A、取消、居中

实现链路：

   Android 点选白色 free 区域
   -> SlamMapView 将屏幕坐标转换为 map 坐标
   -> isFreeForGoal() 校验目标点及周边安全半径
   -> RobotController 发布 /move_base_simple/goal
   -> RobotController 订阅 /move_base/status
   -> SlamMapFragment 根据 SUCCEEDED/ABORTED/REJECTED/PREEMPTED 更新状态

当前版本说明：

1. A/B 点会显示在地图上，A 为蓝色，B 为红色。
2. 目标点必须落在白色可通行区域，且周边约 3 个栅格不能有未知或障碍。
3. 当前 APK 不强制 A/B 必须在黄色设定框内；黄色框主要用于提示 gmapping 设定区域。若现场要求严格 4m x 4m 活动范围，需要后续在 isFreeForGoal() 中增加 configured bounds 硬校验。
4. A-B-A 功能依赖机器人端 move_base，当前 run_android.sh 默认启动 move_base。启动时直接执行：

   /home/xtark/ros_ws/scripts/run_android.sh start

5. 该功能已经安装到 MuMu 侧，下一步是实车验证，不需要仅因文档更新重新编译安装。

七、Android 手工控制和 SafeMode 注意事项

Android 左下角手工按钮和右下角摇杆走同一条速度链路：

   ManualControlFragment / JoystickView -> RobotController.forceVelocity() -> /cmd_vel -> xtark_driver

因此手工按钮也会经过 RobotCA 原有 SafeMode 安全减速。当前 SafeMode 不是完整自主避障，而是“前向碰撞预警 + 安全减速”：

1. WarningSystem 读取激光雷达前方约 +/-40 度范围。
2. 如果前方障碍过近，HUD 会红色预警，warnAmount 增大。
3. SafeMode 开启时，前进速度按 (1 - warnAmount)^2 自动缩小。
4. warnAmount 很高时，前进几乎等于被禁止。

所以如果出现“后退/转向还行，但前进不灵活”的现象，优先看 HUD 是否红色预警，并在车端执行：

   rostopic echo /cmd_vel

按住 Android 前进按钮时，如果 /cmd_vel.linear.x 明显小于设置的人工按钮线速度，通常不是 xtark 没收到命令，而是 Android SafeMode 在发布前已经把速度裁剪了。

详细说明见：

   android\docs\Android手动控制与SafeMode说明.md
