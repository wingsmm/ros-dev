# 导航路径可视化开发方案

更新时间：2026-06-11

## 1. 目标

在 Android 的 `SLAM 地图` 页面上显示 `move_base` 当前规划路径，辅助判断 A-B-A 导航时路线是否合理、是否发生重规划、是否受在线 SLAM 地图跳变影响。

当前基础导航链路已经打通：

```text
Android 设置 A/B
  -> 点击 去 B / 返回 A / A-B-A
  -> 发布 /move_base_simple/goal
  -> move_base 规划并发布 /cmd_vel
  -> 小车到达目标
  -> /move_base/status 返回 SUCCEEDED
```

本方案只做“路径显示”，不改变导航控制逻辑。

## 2. 当前状态

已经具备：

- `/map` 栅格地图显示。
- A/B 点显示。
- 小车位置显示，来源为 `/robot_pose_in_map`。
- `/move_base_simple/goal` 发布。
- `/move_base/status` 订阅。
- `/move_base/cancel` 发布。

尚未具备：

- `/move_base/NavfnROS/plan` 路径订阅。
- `nav_msgs/Path` 到地图折线的转换。
- 在 `SlamMapView` 上绘制全局路径。
- 路径过期、清空、重规划提示。

## 3. 推荐订阅 Topic

优先使用：

```text
topic: /move_base/NavfnROS/plan
type: nav_msgs/Path
frame_id: map
```

备选：

```text
/move_base/GlobalPlanner/plan
/move_base/TrajectoryPlannerROS/global_plan
```

具体以机器人端 `rostopic list | grep plan` 为准。第一版建议先硬编码 `/move_base/NavfnROS/plan`，后续再做 Preferences 配置。

## 4. Android 修改范围

### 4.1 RobotController.java

新增字段：

```java
private Subscriber<Path> moveBasePlanSubscriber;
private final ArrayList<MessageListener<Path>> moveBasePlanListeners;
```

构造函数初始化：

```java
this.moveBasePlanListeners = new ArrayList<>();
```

`refreshTopics()` 中新增：

```java
if (moveBasePlanSubscriber == null) {
    moveBasePlanSubscriber = connectedNode.newSubscriber(
            "/move_base/NavfnROS/plan", Path._TYPE);
    moveBasePlanSubscriber.addMessageListener(new MessageListener<Path>() {
        @Override
        public void onNewMessage(Path path) {
            synchronized (moveBasePlanListeners) {
                for (MessageListener<Path> listener : moveBasePlanListeners) {
                    listener.onNewMessage(path);
                }
            }
        }
    });
}
```

新增方法：

```java
public boolean addMoveBasePlanListener(MessageListener<Path> listener);
public boolean removeMoveBasePlanListener(MessageListener<Path> listener);
```

`shutdownTopics()` 中关闭：

```java
if (moveBasePlanSubscriber != null) {
    moveBasePlanSubscriber.shutdown();
    moveBasePlanSubscriber = null;
}
```

需要 import：

```java
import nav_msgs.Path;
```

### 4.2 SlamMapFragment.java

新增字段：

```java
private MessageListener<Path> moveBasePlanListener;
private long lastPlanTimeMs;
```

`onCreateView()` 中创建 listener：

```java
moveBasePlanListener = new MessageListener<Path>() {
    @Override
    public void onNewMessage(final Path path) {
        final Activity activity = getActivity();
        if (activity == null) {
            return;
        }
        activity.runOnUiThread(new Runnable() {
            @Override
            public void run() {
                if (slamMapView != null) {
                    slamMapView.setNavigationPath(path);
                    lastPlanTimeMs = SystemClock.elapsedRealtime();
                }
            }
        });
    }
};
```

`onResume()` 注册：

```java
controller.addMoveBasePlanListener(moveBasePlanListener);
```

`onPause()` 取消：

```java
controller.removeMoveBasePlanListener(moveBasePlanListener);
```

取消导航时清空路径：

```java
slamMapView.clearNavigationPath();
```

当导航状态为 `SUCCEEDED`、`ABORTED`、`REJECTED`、`PREEMPTED` 时，也建议清空或淡化路径。第一版可先保留最后一条路径，方便观察。

### 4.3 SlamMapView.java

新增字段：

```java
private List<MapPoint> navigationPathPoints = new ArrayList<>();
private final Paint navigationPathPaint = new Paint(Paint.ANTI_ALIAS_FLAG);
```

初始化画笔：

```java
navigationPathPaint.setColor(Color.rgb(30, 144, 255));
navigationPathPaint.setStyle(Paint.Style.STROKE);
navigationPathPaint.setStrokeCap(Paint.Cap.ROUND);
navigationPathPaint.setStrokeJoin(Paint.Join.ROUND);
navigationPathPaint.setStrokeWidth(4.0f);
```

新增方法：

```java
public void setNavigationPath(Path path) {
    navigationPathPoints.clear();
    if (path != null && path.getPoses() != null) {
        for (PoseStamped pose : path.getPoses()) {
            double x = pose.getPose().getPosition().getX();
            double y = pose.getPose().getPosition().getY();
            navigationPathPoints.add(new MapPoint(x, y));
        }
    }
    invalidate();
}

public void clearNavigationPath() {
    navigationPathPoints.clear();
    invalidate();
}
```

`onDraw()` 中建议绘制顺序：

```text
1. 地图 bitmap
2. 规划路径线
3. 黄框/绿框
4. A/B 点
5. 小车位置
```

绘制路径：

```java
private void drawNavigationPath(Canvas canvas) {
    if (navigationPathPoints.size() < 2 || mapBitmap == null || lastResolution <= 0.0) {
        return;
    }

    Path androidPath = new Path();
    boolean started = false;
    for (MapPoint point : navigationPathPoints) {
        float bx = (float) ((point.x - lastOriginX) / lastResolution);
        float by = (float) (mapBitmap.getHeight() - (point.y - lastOriginY) / lastResolution);
        if (!started) {
            androidPath.moveTo(bx, by);
            started = true;
        } else {
            androidPath.lineTo(bx, by);
        }
    }

    navigationPathPaint.setStrokeWidth(4.0f / scale);
    canvas.drawPath(androidPath, navigationPathPaint);
}
```

注意 Java 类名冲突：

```text
nav_msgs.Path 和 android.graphics.Path 同名。
```

建议：

- `RobotController` 和 `SlamMapFragment` import `nav_msgs.Path`。
- `SlamMapView` 里如果同时用到 Android Path，使用完整类名 `android.graphics.Path`，或把 nav_msgs.Path 转换为 `List<MapPoint>` 后再传入 View。

为了减少冲突，推荐 `SlamMapView` 暴露：

```java
public void setNavigationPathPoints(List<MapPoint> points)
```

由 `SlamMapFragment` 完成 `nav_msgs.Path -> List<MapPoint>` 转换。

```bash

rostopic info /move_base/NavfnROS/plan 2>&1 || true
timeout 3 rostopic echo /move_base/NavfnROS/plan -n 1 2>&1 || true
```

在 `watch-nav` 中可选增加：

```bash
rostopic echo /move_base/NavfnROS/plan
```

如果实际 topic 不存在，检查：

```bash
rostopic list | grep -E 'plan|global_plan'
```

## 6. UI 行为建议

第一版保持简单：

- 未发 goal：不显示路径。
- 发 goal 后：显示蓝色全局路径线。
- move_base 重规划：路径线实时替换。
- 取消导航：清空路径。
- 到达目标：保留最后路径 2 到 5 秒后清空，或先不自动清空。

建议调试面板增加一行：

```text
规划路径：已连接 / 未连接；点数 N；上次更新 X 秒前
```

## 7. 验收标准

机器人端：

```bash
rostopic info /move_base/NavfnROS/plan
rostopic echo /move_base/NavfnROS/plan -n 1
```

Android 端：

- 设 A/B 时不显示路线。
- 点 `去 B` 后出现一条蓝色路线。
- 小车移动过程中路线可能刷新。
- 点 `返回 A` 后路线切换到回 A 的路径。
- 点 `A-B-A` 后先显示去 B 路径，到达 B 后切换为回 A 路径。
- 点 `取消` 后路径消失或停止更新。

## 8. 已知限制

- 在线 gmapping 会导致 `map -> odom` 跳变，路径线可能突然重画，这是正常现象。
- 路径显示只代表 move_base 规划意图，不代表小车实际轨迹。
- 如果 Android 仍然能在导航期间发布 `/cmd_vel`，实际轨迹可能偏离路径。后续应增加“导航期间锁定手动速度输出”。
- 复杂环境下应保存地图后切换 `map_server + amcl + move_base`，路径会更稳定。
