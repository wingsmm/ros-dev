# 宇树 L1 对接方案

本文是本仓库里 Unitree / 宇树 L1 雷达落地的主入口。以后讨论 L1 接入、cockpit 可视化、TF、Point-LIO、避障消费时，以本文为准；其它文档只作为资料或历史记录。

## 一句话结论

当前正确落地路径是：

```text
Jetson 跑官方 unitree_lidar_ros2
  -> 发布 /unilidar/cloud + /unilidar/imu
  -> VMware/VM 观测端通过同一 ROS_DOMAIN_ID 订阅
  -> RViz2 先用 Fixed Frame=unilidar_lidar 看原始点云
  -> 原始链路稳定后，再加 base_link 静态 TF
  -> 最后再接 Point-LIO / odom / 避障
```

不要一上来把官方驱动、TF、Point-LIO、odom adapter、cockpit 一键启停绑成一个大栈。先把官方原始点云闭环跑稳。

## 分阶段落地

### 阶段 1：官方原始点云闭环

目标：只证明 L1 官方驱动在 Jetson 上能稳定发布原始点云，VMware/VM 观测端能看见。

链路：

```text
Jetson unitree_lidar_ros2
  -> /unilidar/cloud   sensor_msgs/PointCloud2, frame=unilidar_lidar
  -> /unilidar/imu     sensor_msgs/Imu, frame=unilidar_imu

VMware/VM RViz2
  -> Fixed Frame=unilidar_lidar
  -> PointCloud2=/unilidar/cloud
```

要做：

1. 在 Jetson 上固定串口别名为 `/dev/unilidar_lidar`。
2. 将官方 launch 中的串口路径改为 `/dev/unilidar_lidar`。
3. 在 Jetson 上编译 `unitree_lidar_ros2` 和 `unitree_lidar_sdk`。
4. 在 Jetson 上直接 `ros2 launch unitree_lidar_ros2 launch.py`。
5. 在 VMware/VM 观测端上用同一个 `ROS_DOMAIN_ID` 查 topic 和打开 RViz。

验收：

- Jetson 上雷达节点无串口权限错误。
- VMware/VM 观测端能看到 `/unilidar/cloud` 和 `/unilidar/imu`。
- `/unilidar/cloud` 频率接近 9 Hz。
- `/unilidar/imu` 高频稳定。
- RViz 中点云可见，遮挡雷达时点云变化。

建议命令：

```bash
# Jetson
cd ~/qt/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select unitree_lidar_ros2 unitree_lidar_sdk
source install/setup.bash
ros2 launch unitree_lidar_ros2 launch.py
```

```bash
# VMware/VM 观测端
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=0
ros2 topic list
timeout 12 ros2 topic hz /unilidar/cloud
timeout 12 ros2 topic hz /unilidar/imu

cd jetson/cockpit
bash scripts/start_unilidar_rviz.sh
```

## 阶段 2：接入车体 TF

目标：把雷达坐标系挂到车体坐标系，但不引入 SLAM。

目标 TF：

```text
base_link
  -> unilidar_lidar
  -> unilidar_imu
```

原则：

- 先用 RViz 看 `unilidar_lidar` 的 X/Y/Z 轴，确认实车安装方向。
- 卧放安装时，如果 Z 轴朝前，只在静态 TF 里修正，不改驱动 topic 和 frame 名称。
- `base_link -> unilidar_lidar` 的平移来自实车测量。
- `unilidar_lidar -> unilidar_imu` 只有在确认官方外参或项目需要时再发布，不要猜。

验收：

- `tf2_echo base_link unilidar_lidar` 有稳定输出。
- RViz `Fixed Frame=base_link` 时仍能看到原始点云。
- 点云前后左右与车体方向一致。

## 阶段 3：cockpit 一键化

目标：让 cockpit 做观测入口，而不是把点云渲染塞进 Qt。

保留职责：

- cockpit 本地启动 / 停止 RViz2。
- cockpit 显示 `/unilidar/cloud`、`/unilidar/imu` 是否 alive、频率、publisher。
- cockpit 显示当前使用的 RViz 配置。

谨慎新增：

- 如需“启动 L1 / 停止 L1”按钮，应新增官方 L1 demo 的最小远端入口。
- 不复用已撤回的 `ros2_stack.sh` 语义。
- 不在按钮里隐式启动 Point-LIO 或 odom adapter。

验收：

- 不手动 Add Display 即可打开原始点云视图。
- 面板状态和 `ros2 topic hz` 结果一致。
- 远端 L1 未启动时，面板明确显示无 publisher，而不是误报全栈状态。

## 阶段 4：Point-LIO / odom

目标：在原始 L1 输入稳定、TF 明确后，再接运动观测。

目标链路：

```text
/unilidar/cloud + /unilidar/imu
  -> Point-LIO
  -> /aft_mapped_to_init
  -> odom adapter
  -> /odom + /odom_path + TF
```

注意：

- 这一阶段不是官方截图等价链路。
- 输入频率不稳时不要调 LIO。
- `camera_init -> aft_mapped` 出现百米或千米级漂移时，先回查 `/unilidar/cloud` 和 `/unilidar/imu`。
- 底盘不可用或禁用时，移动 odom 只能来自 L1 + Point-LIO，不从 `/cmd_vel` 伪造。

验收：

- `/unilidar/cloud` 接近 9 Hz。
- `/unilidar/imu` 高频稳定。
- `/cloud_registered` 有输出。
- `/odom` 和 `/odom_path` 有输出且静止时不乱飞。
- 慢速推动车体时 path 连续。

## 阶段 5：下游消费

可选方向：

- 2D 避障：`pointcloud_to_laserscan` 从 `/unilidar/cloud` 或配准点云派生 `LaserScan`。
- 3D 感知：直接消费 `PointCloud2`。
- 导航 / costmap：等 odom 和 TF 稳定后再接。

控制链路保持解耦：

- L1 只负责感知。
- `/cmd_vel` 只负责控制命令。
- 不把控制命令反推成位姿或里程计。

## 不要做什么

- 不要在第一阶段做完整 SLAM 栈。
- 不要把 RViz 现象当作驱动健康证据。
- 不要为了让画面好看乱改 frame 名称或 topic 名称。
- 不要在 cockpit 里隐藏启动复杂远端栈。
- 不要把历史归档 `other/ros2_ws/` 重新推回当前 mirror。
- 不要把本机 WSL build 当作 Jetson 验收。
