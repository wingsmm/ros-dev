# Xtark 相机链路说明

整理日期：2026-06-18

本文只说明两条当前要用的看图链路：

- Android App 怎么从手机端看到机器人端画面。
- PC Qt 怎么从电脑端看到机器人端画面。

深度相机、RK3568 不是当前 Android / Qt 默认看图链路，只在最后说明边界。

---

## 1. Android 看图链路

Android 是 ROS1 客户端。它连接机器人端 ROS Master，然后订阅机器人端发布的压缩图像话题。

```text
Android App
  -> ROS Master http://192.168.1.168:11311
  -> subscribe /image_raw/compressed
  -> receive sensor_msgs/CompressedImage
  -> decode JPEG
  -> show in Android UI
```

机器人端对应链路：

```text
/dev/video0
  -> uvc_camera_node
  -> /image_raw/compressed
```

关键点：

| 项目 | 内容 |
|------|------|
| Android 连接入口 | `http://192.168.1.168:11311` |
| Android 订阅话题 | `/image_raw/compressed` |
| 图像类型 | `sensor_msgs/CompressedImage` |
| 机器人端设备 | `/dev/video0`，UVC 彩色相机 |
| 是否经过 HTTP/MJPEG | 否 |
| 是否使用手机摄像头 | 否 |
| 是否依赖深度相机 | 否 |

Android 无画面时，优先查机器人端：

```bash
rostopic info /image_raw/compressed
rostopic hz /image_raw/compressed
```

如果 `/image_raw/compressed` 没有数据，Android 一定不会有画面。

## 2. PC Qt 看图链路

Qt 当前不是 ROS1 图像订阅客户端。Qt 走 HTTP/MJPEG，从机器人端 `web_video_server` 拉视频流。

```text
PC Qt CameraPage
  -> http://192.168.1.168:8080/stream?topic=/camera/image_raw
  -> web_video_server
  -> read /camera/image_raw
  -> MJPEG frames
  -> show in Qt UI
```

机器人端对应链路：

```text
/dev/video0
  -> uvc_camera_node
  -> /image_raw/compressed
  -> image_transport republish
  -> /camera/image_raw
  -> web_video_server :8080
```

关键点：

| 项目 | 内容 |
|------|------|
| Qt 连接入口 | `http://192.168.1.168:8080` |
| Qt 默认 URL | `http://192.168.1.168:8080/stream?topic=/camera/image_raw` |
| Qt 拉流方式 | HTTP/MJPEG |
| 机器人端 HTTP 源话题 | `/camera/image_raw` |
| 是否直接订阅 ROS1 | 当前否 |
| 是否依赖深度相机 | 否 |

Qt 无画面时，先用浏览器验证：

```text
http://192.168.1.168:8080/stream?topic=/camera/image_raw
```

判断方式：

| 现象 | 说明 |
|------|------|
| 浏览器能出图，Qt 不出图 | 优先查 Qt 页面、URL、拉流代码 |
| 浏览器也不出图 | 优先查机器人端 `web_video_server`、`/camera/image_raw` |
| `/camera/image_raw` 没数据 | 查 republish 或上游 `/image_raw/compressed` |
| `/image_raw/compressed` 没数据 | 查 `/dev/video0` 和 `uvc_camera_node` |

## 3. Android 和 Qt 的区别

| 项目 | Android | PC Qt |
|------|---------|-------|
| 客户端位置 | 手机 / 模拟器 | PC |
| 连接入口 | ROS Master `11311` | HTTP `8080` |
| 使用话题 | `/image_raw/compressed` | `/camera/image_raw` |
| 数据格式 | ROS `CompressedImage` | HTTP/MJPEG |
| 是否经过 `web_video_server` | 否 | 是 |
| 当前定位 | App 内远程看图 | PC 端预览和调试 |

一句话：

```text
Android 看 ROS 话题。
Qt 看 HTTP 视频流。
两者共用机器人端 UVC 相机源头，但出口不同。
```

## 4. 启动脚本怎么理解

一个脚本可以把相机相关节点一起启动，但链路仍然要分开验收。

脚本可以统一启动：

```text
uvc_camera_node
image_transport republish
web_video_server
```

验收必须分开：

| 验收对象 | 检查点 |
|----------|--------|
| Android | `/image_raw/compressed` 是否有数据 |
| Qt | `:8080/stream?topic=/camera/image_raw` 是否能打开 |
| 共同源头 | `/dev/video0` 和 `uvc_camera_node` 是否正常 |

所以不要把“一个脚本启动”理解成“Android 和 Qt 是同一个出口”。

## 5. 不要混进来的链路

### 5.1 深度相机

Orbbec Astra Pro 深度链路用于 RGB-D、点云、RTAB-Map、近场避障等扩展能力。

它不是 Android / Qt 当前默认看图链路。

常见话题：

```text
/camera/depth/image_raw
/camera/depth/points
/camera/ir/image_raw
/camera/color/image_raw
```

如果只是排查 Android 或 Qt 普通画面，不要先查这些话题。

### 5.2 RK3568

RK3568 是独立 ROS2 传感器盒，不是当前 Android / Qt 画面来源。

| 项目 | 内容 |
|------|------|
| IP | `192.168.1.163` |
| ROS | ROS2 Humble |
| 职责 | 传感器采集 |
| 是否负责 Android 画面 | 否 |
| 是否负责 Qt 画面 | 否 |

只有做 ROS2 传感器联调、深度图、点云、RPLidar 数据时，才优先看 RK3568。

## 6. 最小排障顺序

### Android 无画面

```bash
rostopic hz /image_raw/compressed
```

### Qt 无画面

```bash
curl -I "http://192.168.1.168:8080/stream?topic=/camera/image_raw"
```

### Android 和 Qt 都无画面

```bash
ls -l /dev/video0
rostopic hz /image_raw/compressed
rostopic hz /camera/image_raw
pgrep -af 'uvc_camera|republish|web_video_server'
```
