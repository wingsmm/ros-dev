一、当前 Android 两点导航链路

当前目标是让 Android App 在 gmapping 已走过的可通行区域里设置 A/B 点，并通过 move_base 完成两点导航验证。xtark 小车和 Android App 不直接通信，而是在同一套 ROS 网络里通过话题交互。

1.1 连接前提

项值
小车 IP192.168.1.169
App Master URIhttp://192.168.1.169:11311
网络手机/模拟器与小车在同一局域网
小车启动脚本xtark/scripts/android_stack.sh start
Windows 同步启动xtark/scripts/start_android.bat
注意：android_stack.sh 故意不启动 json_base_adapter（PC/Qt JSON 控制用）。两套栈同时抢 /cmd_vel 会冲突。

1.2 小车端提供什么（android_stack.sh）

组件作用
roscoreROS 主节点，监听 11311
xtark_bringup.launch底盘驱动：发布 /scan、/odom，订阅 /cmd_vel
xtark_camera.launch摄像头 → /image_raw/compressed
gmapping激光建图 → /map
move_base自主导航，处理目标点并下发 /cmd_vel
xtark_nav/launch/robot_pose_in_map.launchTF map→base_footprint 转成 /robot_pose_in_map
nav_speed_sync读 App 发来的 /android/nav_speed，动态调整 move_base 自主导航速度上限

1.3 Android 端做什么（RobotController）

App 通过 rosjava 注册节点 android/robot_controller。

订阅（感知与显示）

话题用途
/mapSLAM 地图页面栅格图
/scan激光雷达显示、SafeMode 前方障碍检测
/odom里程计
/image_raw/compressed相机画面
/robot_pose_in_map地图上画小车位置和朝向
/move_base/statusA-B-A 导航状态（成功/失败/取消）

发布（控制与导航）

话题用途
/cmd_vel摇杆、手动按钮 → 直接控底盘
/move_base_simple/goalSLAM 地图点选目标 → 自主导航
/move_base/cancel取消当前导航
/android/nav_speed发 A/B 导航目标前，把 App 当前速度设置同步给 move_base
速度设置的真实含义：App 里的线速度/角速度设置是同一份偏好。手动跑图时，摇杆/按钮按这份设置直接发布 /cmd_vel；切到 A/B 自主导航时，App 会在发送目标前把当前这份设置通过 /android/nav_speed 推给小车端，让 move_base 按相同速度上限规划。

1.4 三条典型交互路径

手动遥控

摇杆 / 手动按钮
  → 读取 App 当前线速度 / 角速度设置
  → RobotController.forceVelocity()
  → /cmd_vel
  → xtark_driver
  → 电机转动

SafeMode 在 App 内根据 /scan 前方扇区（约 ±40°）减速，不是小车端完整避障。

已走过地图 + 车标

gmapping → /map          → App 画已走过地图
gmapping → TF(map→base)  → robot_pose_in_map.launch → /robot_pose_in_map → App 画车标

App 不直接读 TF，因此小车端通过 xtark_nav/launch/robot_pose_in_map.launch 启动桥接节点。

A/B 两点导航

App 在地图上选白格
  → 坐标转换 + 空闲格校验
  → 发目标前同步当前速度设置到 /android/nav_speed
  → /move_base_simple/goal
  → move_base 在当前在线地图上规划路径
  → /cmd_vel → xtark_driver
  → /move_base/status 回 App 更新 UI

1.5 与 PC/Qt 控制的区别

Android 验证栈PC/Qt 栈
启动脚本android_stack.shjson_stack.sh
控制方式ROS 话题（/cmd_vel 等）JSON TCP 8765
冲突点两套栈不要同时占 /cmd_vel

二、11311 做什么？/scan 在哪里？

上一版架构图容易让人误以为所有数据都走 11311。实际上要区分 控制面（11311）和 数据面（话题直连）。

2.1 11311 做什么、不做什么

11311 是 roscore（ROS Master） 端口，负责注册与协调，不承载激光、地图、图像等大数据。

11311 负责11311 不负责
节点注册（谁在线）传输激光点云、地图栅格
话题匹配（谁发布/谁订阅 /scan）传输 /cmd_vel 速度指令本体
参数服务器（如 gmapping 的 xmin）传输相机压缩图
告诉订阅方发布方的 TCP 地址代替 move_base 做路径规划

连接建立过程

1. Android App 连接 http://192.168.1.169:11311
2. 向 Master 注册节点 android/robot_controller
3. 声明：我要订阅 /scan、/map、/robot_pose_in_map …
4. Master 回复：/scan 的发布者在 169 的某个 TCP 端口
5. App 与发布节点直连，激光数据走局域网，不经 11311
一句话：11311 = 电话簿 + 接线员；话题数据 = 节点之间直连。

2.3 /scan 在各处的角色

/scan（sensor_msgs/LaserScan）是整条链路的 核心传感器话题：

环节谁发布谁订阅用途
采集rplidar（bringup 内）—雷达 USB → 点云
滤波滤波节点（若有）—/scan_raw → /scan
建图—gmapping根据 /scan + /odom 更新 /map 和 TF
导航—move_base costmap局部/全局代价地图避障
显示—AndroidHUD 激光扇形
安全—Android SafeMode读前方 ±40° 减速（非完整避障）

android_stack.sh 启动时会先等待 /scan，再启动 gmapping：

wait_for_topic /scan  →  start_gmapping

没有 /scan，gmapping、move_base、App 激光显示都会出问题。

2.4 按功能再看数据流

感知链（含 scan）

激光雷达
  → rplidar（bringup）
  → /scan
      ├→ gmapping        → /map + TF
      ├→ move_base       → 代价地图避障
      └→ Android App     → HUD + SafeMode

地图 + 车标

/scan + /odom → gmapping → /map → App 画已走过地图
                gmapping → TF(map→base_footprint)
                      → robot_pose_in_map.launch
                      → /robot_pose_in_map → App 画车标

手动遥控

App 当前速度设置
  → 摇杆 / 手动按钮
  → /cmd_vel
  → xtark_driver
  → 电机
（与 nav_speed_sync 无关；SafeMode 会先读 /scan 再决定是否减速）

自主导航

App 当前速度设置
  → /android/nav_speed
  → nav_speed_sync
  → dynamic_reconfigure 调整 move_base 速度上限
App → /move_base_simple/goal → move_base
move_base 用当前 /scan + /map + /odom 规划
move_base → /cmd_vel → xtark_driver
move_base → /move_base/status → App

三、Android ↔ 小车交接契约

这部分是当前 Android、后续 Qt/PC、未来 ROS2/网关实现都应对齐的行为契约。UI 可以自研，底层交接尽量保持标准 ROS topic 和清晰状态语义。

3.1 启动边界

模块负责内容不负责内容
小车端 android_stack.sh启动 roscore、底盘、相机、gmapping、move_base、车标 pose、速度同步不保存 Android 任务队列，不维护多航点状态机
Android App显示地图/车标/规划路径，点选目标，发送 goal/cancel，维护 A/B 或多航点任务状态不做全局路径规划，不直接替代 move_base 避障
PC/Qt 后续实现按同一套 topic 和状态语义实现控制/显示不另起一套与 Android 不一致的任务完成判据

3.2 必须稳定的 ROS 接口

方向Topic / 接口类型契约
小车 → App/mapnav_msgs/OccupancyGridSLAM 地图；Android 只允许在已探索 free 区域点选目标。
小车 → App/scansensor_msgs/LaserScanHUD 和 SafeMode 辅助显示；不作为 Android 全局规划输入。
小车 → App/robot_pose_in_mapgeometry_msgs/PoseStamped机器人在 map 坐标系下的位置和朝向，用于地图车标。
小车 → App/move_base/statusactionlib_msgs/GoalStatusArray导航状态来源；任务推进必须基于它。
小车 → App/move_base/NavfnROS/plannav_msgs/Pathmove_base 当前全局规划意图；只表示计划路线，不表示实际轨迹。
App → 小车/move_base_simple/goalgeometry_msgs/PoseStamped导航目标；frame_id 必须是 map。
App → 小车/move_base/cancelactionlib_msgs/GoalID取消当前 move_base 目标；停止/暂停任务都应先取消当前目标。
App → 小车/android/nav_speedgeometry_msgs/Twist发导航 goal 前同步当前速度设置，只影响 move_base 速度上限。
App 或 move_base → 小车/cmd_velgeometry_msgs/Twist底盘速度命令；手动和导航不要同时抢占。

3.3 Frame 与坐标

项约定
地图坐标系map
底盘坐标系base_footprint
车标来源小车端把 TF map→base_footprint 转成 /robot_pose_in_map
目标点 frameAndroid 发布 /move_base_simple/goal 时使用 map
地图点选屏幕坐标必须先转换为 map 坐标，再做 free 栅格校验。

3.4 导航状态语义

Status含义App 行为
PENDING / ACTIVE当前 goal 已进入 move_base 执行链路标记当前目标已被接管，允许后续接受完成状态。
SUCCEEDED当前 goal 到达A/B 可进入完成；多航点任务推进到下一个航点。
ABORTED / REJECTED规划或执行失败停止当前任务，显示失败，不盲目发下一个点。
PREEMPTED目标被取消或被新目标覆盖标记取消/暂停，清理当前规划路径显示。
状态防误判：发出新 goal 后，App 不能立刻把收到的 SUCCEEDED 当成当前目标完成；必须先看到该目标进入 PENDING 或 ACTIVE，再接受后续完成状态。

3.5 任务编排边界

功能当前归属说明
A/B、A-B-AAndroidApp 内维护状态，逐次发送标准 move_base goal。
多航点队列Android下周实现：App 维护 List<Waypoint>，SUCCEEDED 后发下一个 goal。
路径规划move_baseAndroid 只显示 /move_base/NavfnROS/plan，不自己规划。
避障与速度输出move_base + xtark_driver导航期间由 move_base 输出 /cmd_vel。
手动遥控Android直接发布 /cmd_vel；导航期间应避免与 move_base 同时发布。

3.6 Android 与 Qt/PC 对齐要求

Qt/PC 后续不要求复用 Android 代码，但应复用同一套行为定义：

行为统一约定
目标坐标系所有导航 goal 均使用 map。
完成判据以 /move_base/status 的 SUCCEEDED 为准，不以 UI 距离估算为准。
失败处理ABORTED / REJECTED 停止当前任务，不自动跳过。
取消/暂停发送 /move_base/cancel，并清理当前任务显示。
路径显示显示 move_base 发布的 nav_msgs/Path，明确它是规划意图。

3.7 ROS2/网关迁移原则

未来如果引入 ROS2、Nav2、rosbridge 或自定义网关，优先保持上述契约不变，只替换底层传输和机器人端实现。

Android / Qt UI 行为
  -> 目标、状态、路径、速度这些契约不变
  -> ROS1 topic / rosbridge / ROS2 action 只是底层实现差异

短期不建议直接迁移 Android 到原生 ROS2/DDS；更稳的路线是先把 ROS1 标准 topic 行为做稳定，再评估 PC/Qt 或网关层承接 ROS2/Nav2。
