# Xtark 手动控制与底盘反馈链路说明

整理日期：2026-06-23

本文说明 **手动控车**、**底盘反馈** 和 **Qt“机器人”页的实时激光链路**。
相机、地图、导航、RK3568 不在本文范围内。

---

## 1. 总览

Xtark 采用上下位机结构：

- **上位机**：Jetson Nano，运行 ROS1、`xtark_driver`、`xtark_json_bridge`。
- **下位机**：OpenCTR / STM32，负责电机控制、编码器读取、IMU 与电压采样。
- **Android**：直接连接 ROS Master，发布 / 订阅 ROS 话题。
- **PC Qt**：不直连 ROS1，通过 JSON TCP 网关控制和接收反馈。

端到端链路如下：

```text
Android
  -> ROS Master :11311
  -> /cmd_vel
  -> xtark_driver
  -> 串口
  -> OpenCTR / STM32

PC Qt
  -> JSON TCP :8765
  -> xtark_json_bridge
  -> /cmd_vel
  -> xtark_driver
  -> 串口
  -> OpenCTR / STM32

OpenCTR / STM32
  -> 串口反馈帧
  -> xtark_driver
  -> /odom, /imu, /voltage, /xtark/*vel, /xtark/*set
  -> Android 直接订阅 ROS
  -> Qt 经 JSON 收 odom_base / base_status
```

| 端 | 控制入口 | 反馈入口 | 说明 |
|----|----------|----------|------|
| Android | ROS `/cmd_vel` | ROS `/odom`、`/imu`、`/voltage` | ROS1 直连 |
| PC Qt | JSON `cmd_vel` | JSON `odom_base`、`base_status` | 由 `xtark_json_bridge` 转换 |

## 2. 控制下发

### 2.1 Android

Android 是 ROS1 客户端，连接机器人端 ROS Master 后直接发布 `/cmd_vel`。

```text
Android App
  -> ROS Master http://192.168.1.168:11311
  -> publish /cmd_vel
  -> xtark_driver
  -> 串口
  -> 下位机
```

| 项目 | 值 |
|------|----|
| ROS Master | `http://192.168.1.168:11311` |
| 控制话题 | `/cmd_vel` |
| 消息类型 | `geometry_msgs/Twist` |
| 是否经过 JSON 网关 | 否 |

### 2.2 PC Qt

Qt 通过 JSON 网关发速度，机器人端网关再转成 `/cmd_vel`。

```text
PC Qt ManualControlStrip
  -> RobotSession.send_velocity()
  -> JsonGatewayBackend
  -> TCP JSON 192.168.1.168:8765
  -> xtark_json_bridge
  -> publish /cmd_vel
```

| 项目 | 值 |
|------|----|
| Qt backend | `json_gateway` |
| 默认网关 | `192.168.1.168:8765` |
| 网关输出 | `/cmd_vel` |
| Qt 是否直接发布 ROS1 | 否 |

Qt 下发格式为一行一个 JSON：

```json
{"type":"cmd_vel","linear_x":0.10,"linear_y":0.00,"angular_z":0.00}
```

停车：

```json
{"type":"cmd_vel","linear_x":0.00,"linear_y":0.00,"angular_z":0.00}
```

当前交互采用 dead-man 语义：

| 行为 | 结果 |
|------|------|
| 按住按钮 | 持续重发速度，约 `10Hz` |
| 松开按钮 | 立即发 0 |
| JSON 网关超时 | `cmd_timeout_sec=0.5` 秒未收到新速度则发 0 |

Android 手动按钮内部先使用界面坐标符号，`RobotController.publishVelocity()` 发布时再对
`linear.y` 和 `angular.z` 取反；Qt 按钮直接使用 ROS `Twist` 约定。因此源码中的中间符号
看起来相反，但最终 `/cmd_vel` 一致：左移为 `linear.y > 0`，左转为 `angular.z > 0`。

## 3. `/cmd_vel` 到串口协议

Android 和 Qt 最终都会落到 ROS1 `/cmd_vel`。

`/cmd_vel` 消息类型：

```text
geometry_msgs/Twist
```

| 字段 | 含义 |
|------|------|
| `linear.x` | 前后速度 |
| `linear.y` | 横移速度，麦克纳姆轮可用 |
| `angular.z` | 原地旋转角速度 |

`xtark_driver` 订阅 `/cmd_vel` 后，缓存最新 Twist，并按 `control_rate` 周期调用 `SetVelocity(x, y, yaw)` 写串口。MEC 四轮速度换算、PID、轮速闭环在下位机完成。

```text
/cmd_vel
  -> xtark_driver::cmd_vel_callback()
  -> current_twist_
  -> xtark_driver::send_speed_callback()
  -> xtark_driver::SetVelocity(x, y, yaw)
  -> 串口速度帧
```

保护逻辑：

| 项目 | 行为 |
|------|------|
| Twist 有效期 | 最近 `1.0s` 内收到才继续使用 |
| 超时 | 发送 `0,0,0` |
| 常见控制频率 | `50Hz` |

速度控制帧：

```text
byte0   0xAA
byte1   0x55
byte2   0x0B
byte3   0x11                  sendType_velocity
byte4   high(int16(x   * 1000))
byte5   low (int16(x   * 1000))
byte6   high(int16(y   * 1000))
byte7   low (int16(y   * 1000))
byte8   high(int16(yaw * 1000))
byte9   low (int16(yaw * 1000))
byte10  checksum              byte0..byte9 的 uint8 累加和
```

示例：前进 `x=0.10, y=0, yaw=0`

```text
AA 55 0B 11 00 64 00 00 00 00 1F
```

## 4. 底盘反馈到 ROS

下位机通过串口回传底盘状态，`xtark_driver::handle_base_data()` 解析后发布 ROS 话题。

反馈帧类型：

```text
foundType_Packages = 0x06
```

反馈帧结构：

```text
0xAA 0x55 + 长度 + 类型 + payload + checksum
```

核心字段：

| 字节范围 | 数据 | 缩放 / 说明 | ROS 输出 |
|----------|------|-------------|----------|
| `4..9` | 陀螺仪 x/y/z | `int16 / 32768 * 2000 deg/s` 后转 rad/s | `/imu.angular_velocity` |
| `10..15` | 加速度 x/y/z | `int16 / 32768 * 2 * 9.8` | `/imu.linear_acceleration` |
| `16..21` | 姿态角 x/y/z | `int16 / 100 deg`，源码主要使用 yaw | `/imu.orientation` |
| `22..27` | 里程计 x/y/yaw | `int16 / 1000` | `/odom.pose` |
| `28..33` | 里程计增量 dx/dy/dyaw | `int16 / 1000`，再除以 dt 得速度 | `/odom.twist` |
| `34..41` | 四轮实际速度 | `int16` | `/xtark/avel` 到 `/xtark/dvel` |
| `42..49` | 四轮目标速度 | `int16` | `/xtark/aset` 到 `/xtark/dset` |
| `50..51` | 电池电压 | `uint16 / 100` | `/voltage` |

当前源码能确认：`xtark_driver` 直接发布 `/odom`、`/imu`、`/voltage` 和 `/xtark/*` 轮速话题。若某个部署额外启用了 EKF，以对应 launch 为准，不在本文默认假设。

## 5. 如何理解 `/odom`

`/odom` 表示小车在里程计坐标系里的状态，核心分为两组：

| 字段组 | 含义 | 回答的问题 |
|--------|------|------------|
| `x / y / yaw` | 位姿 | 小车现在在哪里、车头朝哪边 |
| `vx / vy / wz` | 速度 | 小车此刻正在怎么动 |

### 5.1 位姿：`x / y / yaw`

| 参数 | 含义 | 单位 |
|------|------|------|
| `x` | 相对启动点的前后累计位移 | m |
| `y` | 相对启动点的左右累计位移 | m |
| `yaw` | 相对启动方向的车头朝向角 | rad |

示例：

```text
x = 1.20, y = 0.30, yaw = 0.00
```

表示小车相对启动点向前约 `1.2m`、侧向偏移约 `0.3m`，车头方向基本没变。

### 5.2 速度：`vx / vy / wz`

| 参数 | ROS 字段 | 含义 | 单位 |
|------|----------|------|------|
| `vx` | `/odom.twist.twist.linear.x` | 前后方向速度 | m/s |
| `vy` | `/odom.twist.twist.linear.y` | 左右横移速度 | m/s |
| `wz` | `/odom.twist.twist.angular.z` | 绕 Z 轴旋转角速度 | rad/s |

在本项目里：

```text
/odom.pose
  = 反馈帧里的累计 x / y / yaw

/odom.twist
  = 反馈帧里的 dx / dy / dyaw 除以时间差 dt
```

所以 `vx / vy / wz` 是底盘反馈出来的估算实际速度，不是 Qt 或 Android 下发的目标速度。

## 6. 反馈到 Qt

Qt 反馈不直接读 ROS，而是由 `xtark_json_bridge` 转成 JSON 推送。

### 6.1 `odom_base`

来源：ROS `/odom`

```text
/odom
  -> xtark_json_bridge
  -> JSON odom_base
  -> JsonGatewayBackend
  -> RobotSession.odom_updated
  -> RobotTelemetryBinder
  -> RobotHudBar / RobotTelemetryPanel
```

示例：

```json
{"type":"odom_base","stamp_ms":1718688000123,"x":2.04,"y":-0.31,"yaw":0.05,"linear_x":0.0,"linear_y":0.0,"angular_z":0.0}
```

| JSON 字段 | ROS 来源 | 单位 |
|-----------|----------|------|
| `x` | `/odom.pose.pose.position.x` | m |
| `y` | `/odom.pose.pose.position.y` | m |
| `yaw` | `/odom.pose.pose.orientation` 转 yaw | rad |
| `linear_x` | `/odom.twist.twist.linear.x` | m/s |
| `linear_y` | `/odom.twist.twist.linear.y` | m/s |
| `angular_z` | `/odom.twist.twist.angular.z` | rad/s |

补充：如果 `/odom.twist` 全为 0 但 `/odom.pose` 在变化，`json_base_adapter_node.py` 会用相邻位姿差分估算速度，避免 UI 速度长期显示 0。

### 6.2 `base_status`

来源：ROS `/voltage`

```text
/voltage
  -> xtark_json_bridge
  -> JSON base_status
  -> JsonGatewayBackend
  -> RobotSession.base_status_updated
  -> RobotTelemetryBinder
  -> RobotHudBar / RobotTelemetryPanel
```

示例：

```json
{"type":"base_status","stamp_ms":1718688000456,"online":true,"estop":false,"battery_v":11.59,"mode":"auto","error_code":0}
```

| JSON 字段 | 来源 | 当前含义 |
|-----------|------|----------|
| `online` | 网关占位 | 固定 `true` |
| `estop` | 网关占位 | 固定 `false` |
| `battery_v` | `/voltage` | 电池电压，单位 V |
| `mode` | 网关占位 | 固定 `"auto"` |
| `error_code` | 网关占位 | 固定 `0` |

当前真实有效字段重点看：

| 消息 | 字段 |
|------|------|
| `odom_base` | `x/y/yaw/linear_x/linear_y/angular_z` |
| `base_status` | `battery_v` |

### 6.3 Qt 机器人页激光与告警

```text
/scan
  -> xtark_json_bridge
  -> laser_scan JSON
  -> RobotSession.laser_scan_updated
  -> LaserScanView
```

- `laser_scan` 默认 10Hz，下发原始 `frame_id`、角度和距离；无效距离为 `null`。
- Qt 不生成 Mock 激光；没有真实帧时显示“等待激光数据”，超过 1 秒显示“激光数据超时”。
- Qt 每次连接以第一帧 `odom_base.x/y` 为 `startPos`，机器人页使用 `current - startPos` 绘制首帧相对原点；原始 odom 仍保留给 HUD。切换页面不重置，重启 Qt 或重新连接后重置。
- 当前 MEC + XAS 外参约为 `base_footprint -> laser: x=0.05m, yaw=pi`，Qt 绘制时将扫描点变换到车体坐标。
- `scan_warning` 使用完整分辨率 `/scan`，不受显示抽样影响。
- 当前 `scan_warning` 仍按原始扫描角 `+-40 deg` 取最短距离，没有 Android 的转速修正，也没有应用 `yaw=pi`；该告警方向尚需真车确认，默认关闭 SafeMode。

## 7. 反馈到 Android

Android 不使用 JSON 网关，直接订阅 ROS 话题：

| 数据 | ROS 话题 | 说明 |
|------|----------|------|
| 里程计 / 速度 | `/odom` | 与 Qt `odom_base` 同源 |
| IMU | `/imu` | 纯 IMU 数据 |
| 电压 | `/voltage` | 与 Qt `base_status.battery_v` 同源 |

`odom_base` / `base_status` 是 Qt 网关协议消息，不是机器人端原生 ROS 话题。

## 8. Qt 实现对照

当前 Qt 反馈链路：

```text
JsonGatewayBackend
  -> RobotSession
  -> RobotTelemetryBinder
  -> RobotHudBar / RobotTelemetryPanel / TelemetryDetailsStrip
```

关键文件：

| 文件 | 职责 |
|------|------|
| `pc/qt_client/backends/json_gateway_backend.py` | 连接 TCP JSON 网关，收发消息 |
| `pc/qt_client/core/robot_session.py` | 保存 `last_odom` / `last_base_status`，发出 Qt 信号 |
| `pc/qt_client/core/robot_telemetry_binder.py` | 把 session 反馈绑定到 HUD 和详情面板 |
| `pc/qt_client/gateway/json_telemetry.py` | 统一格式化速度、位姿、电压 |
| `pc/qt_client/ui/widgets/robot_telemetry_panel.py` | 显示 `base_status` 和 `odom_base` |
| `pc/qt_client/ui/pages/robot_workspace_page.py` | 工作区顶栏 HUD |
| `pc/qt_client/ui/pages/camera_page.py` | 摄像头页复用 telemetry binder |
| `pc/qt_client/ui/pages/robot_page.py` | 组合激光视图、工具栏和手动按钮 |
| `pc/qt_client/ui/widgets/laser_scan_view.py` | 激光坐标转换、图元绘制和视图交互 |

实现约束：

- 页面层不直接读 TCP。
- 页面层不直接订阅 ROS。
- HUD 和详情面板共用同一个 `RobotSession`。
- `CameraPage` 只组合页面和手动控制按钮，不自己维护底盘状态。
- Qt 顶部“停止”与手动区“停止”只发送零速度，不是硬件急停，也不实现 Android 导航计划暂停/恢复。
- Qt 当前明确不移植 Android 摇杆、航点、GPS 和 Wi-Fi 到“机器人”页。

## 9. 最小排障

### 控车无效

先看机器人端 `/cmd_vel`：

```bash
rostopic info /cmd_vel
rostopic hz /cmd_vel
rostopic echo /cmd_vel
```

如果 `/cmd_vel` 有数据但车不动，再看驱动和串口：

```bash
rosnode info /xtark_driver
ls -l /dev/ttyTHS1
```

### Qt 没有反馈

机器人端：

```bash
rostopic hz /odom
rostopic echo /voltage
ss -lnt | grep 8765
```

Qt 侧：

```text
确认 backend_type=json_gateway
确认 JsonGatewayBackend 已连接 192.168.1.168:8765
确认 RobotSession 收到 odom_base / base_status
```

### Android 没有反馈

```bash
rostopic hz /odom
rostopic hz /imu
rostopic echo /voltage
```

Android 侧只检查 ROS Master、话题名和消息类型，不检查 JSON 网关。

## 10. 维护边界

- 手动控制统一以 `/cmd_vel` 为最终入口。
- Android 以 ROS 话题为准。
- Qt 以 JSON 网关为准。
- 串口速度帧以 `xtark_driver::SetVelocity()` 为准。
- 串口反馈帧以 `xtark_driver::handle_base_data()` 为准。
- 不把 Qt 的 `odom_base` / `base_status` 写成 ROS 原生话题。
- 不把 `/odom_raw`、EKF、地图位姿写成固定链路，除非当前部署代码明确存在。
