# Xtark 激光里程计实验方案

整理日期：2026-06-18

本文说明一个**实验方案**：使用现有 2D 激光雷达 `/scan` 估算里程计，生成 `/odom_laser`，用于对比或后续替代轮子里程计。

结论先行：

```text
方案可行，但不要一上来替换主线 /odom。
先并行跑 /odom_laser，对比稳定性，再决定是否接入 gmapping / move_base。
```

---

## 1. 背景

当前主线里程计来自底盘：

```text
OpenCTR / STM32 下位机
  -> 编码器里程计反馈帧
  -> xtark_driver
  -> /odom
```

这条链路的优点是频率高、与底盘控制一致；缺点是麦克纳姆轮容易受打滑、地面摩擦、横移误差影响。

激光里程计的思路是：

```text
/scan 前后两帧
  -> 激光扫描匹配
  -> 估算 dx / dy / dyaw
  -> 发布 /odom_laser
```

它不需要新增硬件，使用当前 RPLidar 的 `/scan` 即可先试。

---

## 2. 目标

第一阶段目标不是替换主线，而是做对照实验：

```text
轮子里程计：/odom
激光里程计：/odom_laser
```

对比内容：

| 对比项 | 说明 |
|--------|------|
| 直线前进 | `/odom` 和 `/odom_laser` 的 x 是否一致 |
| 原地旋转 | yaw 是否稳定、是否漂移 |
| 横移 | 麦轮横移时 `/odom_laser` 是否比轮子 odom 更可信 |
| 静止 | 车不动时 `/odom_laser` 是否抖动 |
| 环境变化 | 有人走动、长走廊、大空场时是否失稳 |

---

## 3. 推荐实现

推荐先使用 `rf2o_laser_odometry` 这类 ROS1 激光里程计节点。

仓库已提供独立实验包（**不碰主线**）：

```text
xtark/xtark_laser_odometry/
  launch/rf2o_odom_laser.launch
  config/rf2o_laser_odometry.yaml
  README.md
```

轻量启停脚本（可选，不并入 `robot_stack.sh` / `android_stack.sh`）：

```text
xtark/scripts/laser_odom_experiment.sh          # 仅 rf2o 旁路
xtark/scripts/laser_odom_compare_stack.sh     # Qt 对照 + rosbag（推荐现场测）
```

**现场对照**（各栈独立，需先手动 `robot_stack.sh stop` 避免冲突）：

```bash
robot_stack.sh stop
laser_odom_compare_stack.sh start
laser_odom_compare_stack.sh record
# Qt 192.168.1.169:8765 低速控车
laser_odom_compare_stack.sh stop
robot_stack.sh start
```

每个脚本只有：`start | stop | record | logs`，不互相调用。

部署到机器人后：

```bash
cd ~/ros_ws && catkin_make && source devel/setup.bash
roslaunch xtark_laser_odometry rf2o_odom_laser.launch
# 或
~/ros_ws/scripts/laser_odom_experiment.sh start
```

建议话题规划：

| 数据 | 话题 |
|------|------|
| 激光输入 | `/scan` |
| 轮子里程计 | `/odom` |
| 激光里程计 | `/odom_laser` |
| 激光里程计 TF | 实验阶段建议先关闭或单独隔离 |

不要直接让激光里程计发布成 `/odom`，避免覆盖当前主线。

---

## 4. 实验链路

```text
RPLidar
  -> /scan
  -> rf2o_laser_odometry
  -> /odom_laser

xtark_driver
  -> /odom

对比：
  /odom_laser vs /odom
```

第一阶段只观察：

```bash
rostopic hz /scan
rostopic hz /odom
rostopic hz /odom_laser
rostopic echo /odom_laser
```

如果需要记录对比：

```bash
rosbag record /scan /odom /odom_laser
```

---

## 5. 接入顺序

### 阶段一：并行观察

只新增 `/odom_laser`，不改 gmapping、move_base、Android、Qt。

验收标准：

| 项 | 标准 |
|----|------|
| 节点稳定 | `/odom_laser` 持续发布 |
| 静止稳定 | 静止时 x/y/yaw 不明显漂移 |
| 运动合理 | 前进、旋转、横移趋势正确 |
| 不影响主线 | `/odom`、`/scan`、Android、Qt 原功能不变 |

### 阶段二：让 gmapping 试用

如果 `/odom_laser` 表现稳定，可以单独开一套实验 launch，让 gmapping 使用激光里程计。

注意：

- 不要改现有主线 launch。
- 使用新 launch 或参数开关。
- 保留回退到 `/odom` 的方式。

### 阶段三：再考虑 move_base

move_base 对 odom 稳定性要求更高，不建议第一步就切。

只有在以下条件满足后再试：

| 条件 | 说明 |
|------|------|
| `/odom_laser` 静止不漂 | 不然局部规划会抖 |
| 旋转方向正确 | yaw 正负方向不能反 |
| TF 链完整 | `odom -> base_footprint` 或等效链路清晰 |
| 可快速回退 | 出问题能立刻切回轮子 `/odom` |

---

## 6. 优点和风险

优点：

| 优点 | 说明 |
|------|------|
| 不新增硬件 | 当前 2D 雷达即可试 |
| 可减轻轮子打滑影响 | 运动估计来自环境匹配 |
| 适合作为对照 | 可判断轮子 odom 是否明显漂 |

风险：

| 风险 | 说明 |
|------|------|
| 环境依赖强 | 墙、桌腿、固定障碍越多越稳 |
| 长走廊可能退化 | 几何特征少，匹配容易漂 |
| 大空场可能不稳 | 激光可见结构不足 |
| 动态物体影响 | 人、椅子移动会干扰匹配 |
| TF 容易冲突 | 不能同时有两个节点抢发同一条 odom TF |

---

## 7. 和 IMU / 编码器的关系

本实验不是取消底盘控制，也不是不用编码器。

| 数据 | 当前作用 |
|------|----------|
| `/cmd_vel` | 仍然控制底盘 |
| `/odom` | 轮子编码器里程计，主线继续保留 |
| `/odom_laser` | 激光里程计实验输出 |
| `/imu` | 当前主线未使用，可作为后续融合预留 |

如果后续要做更稳的方案，可以考虑融合：

```text
/odom        轮子里程计
/odom_laser  激光里程计
/imu         IMU
  -> robot_localization / EKF
  -> /odom_fused
```

但这属于后续阶段，不建议和第一轮实验混在一起。

---

## 8. 不要做什么

- 不要一开始就把 `/odom_laser` remap 成 `/odom`。
- 不要直接改主线 bringup / gmapping / move_base launch。
- 不要让两个节点同时发布同一条 `odom -> base_footprint` TF。
- 不要把激光里程计写成“必然优于轮子里程计”。
- 不要在大空场或动态人群环境下直接下结论。

**bag 内数值分析**（Python 读 bag）：

| 项 | 结果 |
|----|------|
| Qt 遥控 | 791 条 `/cmd_vel`，其中 613 条非零；平均 \|vx\|≈0.032 m/s，\|wz\|≈0.136 rad/s |
| 轮子 `/odom` 全程位移 | Δx≈-0.77 m，Δy≈-0.01 m，Δyaw≈-109°，路程约 0.77 m |

**rf2o 日志**：大量 `Waiting for laser_scans....`；节点在听 `/scan`，但运行期几乎未产出 `/odom_laser`（与 bag 中 0 条一致）。常见原因：`/scan` 含 Inf/NaN（rf2o 非 REP-117）、或 `init_pose_from_topic` 未置空。

**本次结论**：

| 项 | 结论 |
|----|------|
| Qt → `/cmd_vel` → 底盘 | **通过**（bag 有连续遥控指令） |
| 轮子 `/odom` | **通过**（频率与位移合理） |
| `/odom_laser` 对照 | **未通过**（本次无有效激光里程计数据） |
| 阶段二（接 gmapping） | **暂缓**，先修 rf2o 与 `/scan` |

**下一步**：

1. `rostopic echo /scan -n 1` 查 `inf`/`nan`；必要时换 artivis rf2o 补丁或激光滤波。
2. `record` 默认去掉 `/tf`，只录 `/cmd_vel /odom /odom_laser /scan`。
3. 重跑：`laser_odom_compare_stack.sh start` → `record` → Qt 低速控车 → `stop`，确认 bag 里 `/odom_laser` 有数据后再做对比。
